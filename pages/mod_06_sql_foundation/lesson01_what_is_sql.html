Overview

A high-level summary of the topic

SQL

SQL is the standard language that data professionals use to ask questions of a database and get back exactly the rows they need.

Think of a database like a filing cabinet at work: the cabinet holds all of your company's records, each drawer stores one category of data, every folder in that drawer is a single customer or order, and the label on each folder tells you what field of information it contains. SQL is the request slip you hand to the clerk — you describe exactly what you want, and the clerk retrieves it in seconds, even when there are millions of folders.

SQL

The request slip — describes exactly what you need

One slip works at every filing cabinet, anywhere in the world.

Database

The filing cabinet — holds every record in one place

Thousands of drawers, millions of folders, one organized system.

Tables, Rows & Columns

Drawers of labeled folders — one record per folder

Each row is one folder; each column is a label printed on every folder.

SELECT Query

Your retrieval request — name the drawer and columns

Fill in the drawer name and column labels — the clerk does the rest.

SQL is one of the highest-return skills in data work — a single well-written query can answer a business question in seconds that would take hours to answer manually in a spreadsheet.

Key Takeaways

The most important ideas to remember

One Language, Every Platform

The same SELECT query you write today transfers to PostgreSQL, MySQL, Snowflake, and BigQuery — learn it once and it covers nearly every data platform you'll encounter at work.

portability cross-platform SQL standard

Databases Handle Billions of Rows

Excel tops out at roughly one million rows and slows down before that limit — a database returns the same data to 100 users at once in seconds, with no file to open or download.

scalability Excel vs SQL performance

SQL Enforces Column Data Types

Every column is declared as text, number, or date when the table is built — so SQL rejects invalid values automatically before they corrupt your analysis, unlike Excel where any cell accepts any value.

data types schema validation

Key Concepts

SQL, databases, tables, and the SELECT statement

SQL

The standard language for reading data in any relational database

The Language

SQL (Structured Query Language) is the standard language for reading and writing data in relational databases. You write a question — SQL hands back the exact rows you need.

SQL vs. Excel

Excel SQL
Scale Slow past 100k rows ✓ Millions of rows
Multiple users ✗ One at a time ✓ Thousands at once
Data types Mix freely ✓ Strict per column
SQL 
-- Ask the database for all customers
SELECT *             -- * returns every column
FROM customers;      -- the table you are reading

SQL runs the same way whether you use PostgreSQL, MySQL, Snowflake, or BigQuery — learning it once covers all of them.

Database

An organized system for storing and serving data reliably

Storage

A database is a collection of structured data managed by software called a database management system (DBMS). It stores data in tables and lets many users query the same data at the same time.

What a Database Guarantees

Data persists after shutdown guaranteed ✓
Each column has a fixed type enforced ✓ — no mixing text and numbers
Thousands of users simultaneously concurrent ✓ — all reading at once
SQL 
-- List every table available in this database
SELECT table_name               -- the column you want
FROM information_schema.tables  -- a built-in catalog table
WHERE table_schema = 'public';  -- limit to the public schema

Connect to the right database first. Every query runs inside one specific database — like opening the correct filing cabinet before you search for anything.

Tables

Rows store records; columns store attributes of those records

Structure

A table is a grid of data inside a database. Every row is one complete record — one customer, one order, or one product. Every column holds one specific attribute of that record, such as a name, date, or price.

Row vs. Column

Row Column
Represents One record One attribute
Example 101 | Maria | NYC city
Changes with Each new record added Table definition
SQL 
-- Each row is one customer; each column is one attribute
SELECT customer_id,   -- column: a unique number per customer
       name,          -- column: the customer's full name
       city           -- column: the city they live in
FROM customers;       -- one row returned per customer

A table can hold millions of rows but usually a small, fixed set of columns. Columns define the shape; rows fill it in.

SELECT

The command that asks the database to return specific data

First Query

A SELECT statement is the most common SQL query. You list the columns you want after SELECT, then name the table after FROM. The database returns every matching row.

SQL Keyword Reference

Keyword Meaning Example
SELECT Choose columns to return SELECT name, city
FROM Name the table to read from FROM customers
* Wildcard — return all columns SELECT *
; Marks the end of a statement FROM orders;
SQL 
SELECT name,     -- return the name column
       city      -- return the city column
FROM customers;  -- read from the customers table

Every SELECT needs a FROM. Without it, the database doesn't know which table to look in. Always pair the two together.

Code Examples

Hands-on code snippets to explore the concepts

01

Select All Columns

Beginner Customers SELECT * wildcard

What This Does

This query returns every column from the customers table. The wildcard * means "all columns" — useful when you first open a table and don't yet know what's in it.

select_all.sql 
-- Return every column from the customers table
SELECT *          -- * means all columns; no need to list them
FROM customers;   -- name the table you want to query
Terminal $ psql -c "SELECT * FROM customers;"
customer_id name city
101 Maria New York
102 James Chicago

Use SELECT * to explore a new table — once you know which columns you need, name them explicitly so your query stays fast on large tables.

02

Choose Specific Columns

Beginner Products column list SELECT

What This Does

This query retrieves only the name and price columns from a products table. The database ignores every other column — your results are smaller and faster to load.

select_columns.sql 
-- Get product names and prices only; skip all other columns
SELECT name,      -- first column you want
       price      -- second column, separated by a comma
FROM products;    -- table that holds this data
Terminal $ psql -c "SELECT name, price FROM products;"
name price
Laptop 1200
Phone 800

The order you list columns in SELECT controls the order they appear in your results — the database ignores the order columns are stored in the table.

03

Query Any Table

Beginner Orders FROM semicolon

What This Does

This query pulls three columns from an orders table. The same SELECT … FROM … pattern works on any table — you only change the column names and the table name after FROM.

select_orders.sql 
-- Retrieve three columns from the orders table
SELECT order_id,       -- unique number for each order
       customer_name,  -- who placed the order
       total_amount    -- value of the order in dollars
FROM orders;           -- semicolon ends the SQL statement
Terminal $ psql -c "SELECT order_id, customer_name, total_amount FROM orders;"
order_id customer_name total_amount
1001 Maria 250.00

Every SQL statement must end with a semicolon — forgetting it is the most common beginner mistake, and most tools will just wait silently instead of running your query.

Common Mistakes

Frequent errors and how to avoid them

Querying the Database Name Instead of a Table

Writing the database name after FROM causes an error — SQL expects a table name there.

Pitfall

FROM must be followed by a table name, not the database name. Writing FROM company_db when company_db is your database raises an error — the database is the container you connect to, and tables are the objects inside it that hold rows of data.

Wrong — querying the database name 

SELECT *
FROM company_db;

Correct — querying a table inside the database 

SELECT *
FROM employees; -- employees is a table inside company_db

Think of the database as the filing cabinet and each table as a labeled drawer — you open the cabinet first (connect to the database in your tool), then pull from a specific drawer (query a table by name).

Writing SELECT Without a FROM Clause

Omitting FROM raises a syntax error — SQL cannot know which table to search.

Pitfall

Every SELECT that reads real data must include a FROM clause naming the source table. Writing SELECT name; raises a syntax error because SQL has no table to search.

Wrong — no FROM clause 

SELECT name;

Correct — SELECT paired with FROM 

SELECT name       -- column you want to retrieve
FROM customers;   -- table that holds this data

SELECT and FROM are always a pair — SELECT names what columns you want, and FROM tells SQL where to find them.

Using a Column Name That Doesn't Match the Table

SQL column names must match the table definition exactly — a typo or wrong name raises an error.

Pitfall

SQL looks for the exact column name defined when the table was created. Writing customer when the column is called customer_id raises an error — the underscore, suffix, and casing all matter.

Wrong — column name doesn't exist 

SELECT customer
FROM customers;

Correct — exact column name from the table 

SELECT customer_id  -- exact name defined in the table
FROM customers;     -- table that contains this column

Before writing a query on a new table, run SELECT * FROM table_name; first — the results show you the exact column names you must use in every subsequent query.
